## 页面与样例锚点

- `/demo/list`：运单模板。历史为86条、20条/页、末页81–86；本轮重新读取总数，不硬编码旧数据。
- `/demo/list/form`：通过列表“新建运单”核实。旧记录的 `/demo/form` 是误路径，不复制进报告。
- `/demo/components`：按钮、输入、弹窗、上传与预览等示例入口；确认状态能否通过真实操作触发。
- `/system-config/master-data`：按可见导航或已确认链接选择 `group`／`resource`；相同聚合路由的不同资源需分别记录。费用项、汇率、字典、国家、Zone等不互相代测。
- 主数据 Mock 的国家样例有分页与长文本；名称选择搜索 `__mock_error__`、重复编码可触发特定失败。只在当前文档及页面支持时使用，不推定所有控件都实现相同开关。

关键历史纠偏（用来指导取证，不预设当前结果）：

- UI-TPL-004：链接实际曾为 `#165DFF`，规范为 `#046EFC`。测渲染链接本身，不用父元素颜色代替。
- UI-TPL-019：原前置没有“持久会话”；刷新去登录页必须直接对照原预期，不新增条件改判受阻。
- UI-TPL-028：内容区Spin与查询按钮loading分别量测；不能因为缺慢请求就忽略已见的按钮缺状态。
- UI-TPL-011：固定300ms详情加载曾可测到骨架、关闭和迟到响应；该范围可以通过，不能外推任意延迟及真实服务。
- UI-TPL-032/033：禁用属性、颜色不代替不能输入／点击和恢复行为；分别取证。
- UI-TPL-038：失败后点击重试又失败，不证明“恢复成功”。预置失败卡也不能替代真实选择文件的整段流程。

## 取证与复测

每条证据标 `evidence_id`、用例与步骤、当前URL、时间含时区、viewport／zoom、样例／角色／基线、证据类型及局限。静态截图、只读DOM、计算样式、真实UI操作、源码分析、历史证据重判要分开。历史证据保留原时间，不标成本次实测。

视觉差异优先取整页上下文和实际控件截图，并读取 `getComputedStyle`、实际内容内层和bounding rect。动态状态保存触发前后及时间顺序；颜色transition未稳定时注明瞬态，复测稳定态后才作稳定色值判定。不要事后将不同时刻数据拼成“同一瞬间”证据。

测试对象的改动指纹至少覆盖未提交diff、暂存diff及相关未跟踪文件路径／哈希；不将凭据或无关私有文件收进证据。新Build只复测受影响点及必要相邻状态，未重跑项注明沿用历史依据。

缺陷修复闭环：`待修改 → 待复测 → 已关闭／复测不通过`。状态变更绑定新的运行基线和证据；“开发说已改”只能进入待复测。用例仍有受阻分支时，关闭已修缺陷不等于整条用例通过。
